# US software-development contact collector — package (2026-11-14)

A bounded, resumable collector that builds a recruiter-style contact list from
**publicly disclosed** email addresses of US-based software-development
profiles, plus the dataset produced by the first run.

## How it works

```
discovery                         enrichment per profile
─────────────────────────────     ──────────────────────────────────────────────
GitHub user search                GET /{login}                  → name, company,
  location:"United States"                                        location, bio
  +(role keywords)                GET /{login}?tab=repositories → own repos
  10 req/min, 100 users/query     GET /{owner}/{repo}/commits?author={login}
        │                                                        → SHA list
        ▼                         GET /{owner}/{repo}/commit/{sha}.patch
  candidate logins                                               → From: Name <email>
        │                                                             │
        ▼                                                             ▼
  US location filter ──────────────────────────────────────► dedupe + classify
  role-relevance score                                              │
                                                                    ▼
                                                    emails.csv / per-person sheet
```

Key design points:

1. **Attribution, not guessing.** An address is attached to a profile only when
   GitHub's own `commits?author=<login>` filter attributes that commit to the
   account. Commit authors from other people in shared repos are therefore not
   mis-attributed.
2. **Source of truth is public data.** Profile fields, public repo lists, and
   the public `.patch` endpoint (which exposes the `From:` line of a commit).
   Nothing behind a login, no API token required, no auth bypass.
3. **Pacing.** Search API is capped at 10 requests/min unauthenticated; HTML
   requests are serialised by a shared pacer (~0.45 s default, jittered) across
   workers. HTTP 429/403 responses trigger backoff.
4. **Resume.** Findings append to `emails.jsonl`; processed logins go to
   `processed.json`. Re-running continues instead of re-scraping.
5. **Filters.** `us_match` (us / maybe / non_us / unknown), `role_score` from
   bio+company+repo signals, `email_type` (personal / corporate / education /
   github_noreply / disposable). Noreply addresses are dropped by default
   because GitHub does not deliver mail to them.
6. **Opt-outs.** `--exclude blocklist.txt` (one address or `@domain` per line)
   is applied on every run.

## Usage

```bash
# default run: 100 US software-dev candidates, 2 repos and 3 commits each
python gh_email_scraper_20261114.py run --limit 100 --out out_us_devs

# larger / different sample: change the shuffle seed, reuse processed state
python gh_email_scraper_20261114.py run --queries-file queries_v2_20261114.txt \
    --limit 150 --seed 991 --out out_us_devs

# finish or re-run whatever is still pending in an existing output dir
python gh_email_scraper_20261114.py enrich --out out_us_devs

# add specific people you already know
python gh_email_scraper_20261114.py run --seed-logins logins.txt --out out_us_devs

# emails from arbitrary public profile/repo pages (GitLab, dev.to, personal sites…)
python gh_email_scraper_20261114.py pages --urls urls.txt --out out_pages

# totals for an output directory
python gh_email_scraper_20261114.py stats --out out_us_devs
```

Useful flags: `--limit`, `--max-emails`, `--concurrency` (default 3),
`--pace` (seconds between HTML requests), `--repos-per-user`,
`--commits-per-repo`, `--min-score`, `--include-unknown-location`,
`--include-noreply`, `--exclude`.

### Output schema (`us_dev_email_contacts_20261114.csv`)

`email, name, login, company, location, us_match, us_evidence, role_score,
role_signals, email_type, email_source, repo, commit_sha, commit_date,
commit_subject, profile_url, collected_at`

Every row is reproducible: `profile_url` + `repo` + `commit_sha` let you open
the exact public commit that disclosed the address.

## Data quality caveats

- **Unverified addresses.** No SMTP/MX probing was performed, so bounce rates
  are unknown; run the list through a verifier before sending.
- **Self-reported location.** US status comes from the profile's location field.
  It is a strong but imperfect signal (people relocate, some write "Remote").
  Rows are labelled `us` or `maybe`, not "confirmed resident".
- **Corporate addresses** may be shared role mailboxes or a previous employer's
  domain; `role_score` and `company` help triage.
- **~5% students** (`.edu` domains) — filter by `email_type` if you only want
  industry experience.
- **Noreply addresses are excluded** by design; including them
  (`--include-noreply`) gives coverage but those mailboxes do not receive mail.
- **Scale limits without a token:** GitHub search allows 10 unauthenticated
  requests/min, and profile/repo/commit pages are paced to stay polite. Bigger
  volumes mean more batches (state resumes), not higher concurrency. Raising
  `--concurrency` without raising `--pace` does not increase throughput, since
  all HTML requests share one pacer.

## Compliance notes (read before outreach)

- All addresses here were published by their owners on public GitHub profiles
  or commit metadata. That makes collection lawful in most jurisdictions, but
  **it does not by itself authorise unsolicited marketing**.
- US: CAN-SPAM requires accurate headers, a physical postal address, a working
  opt-out, and honouring opt-outs within 10 business days. Cold B2B mail is
  permitted; purchased-list rules and deceptive subjects are not.
- EU/UK: PECR/GDPR generally require consent or a soft opt-in/legitimate-interest
  assessment for B2B email; include an opt-out and a privacy notice, and be
  ready to delete on request (`--exclude` supports address and domain blocks).
- California: CCPA/CPRA gives deletion/opt-out rights for consumer data.
- Keep the provenance columns (`repo`, `commit_sha`, `collected_at`). They are
  what lets you answer "where did you get my address?" and action a deletion.
- Do not use this for bulk spam, and do not point it at login-walled services
  (LinkedIn, Wellfound, etc.) — that breaches those platforms' terms. `pages`
  mode is for public pages you are allowed to fetch; it does not authenticate.

## Extending

- Add queries: `--query 'location:"Austin" "platform engineer" type:user'`
  (repeatable) or a `--queries-file` with one query per line.
- Widen geography: edit `US_CITIES` / `NON_US` in the script.
- Different role focus: edit `ROLE_KEYWORDS` and `--min-score`.
- Non-GitHub sources: `pages` mode extracts addresses plus surrounding context
  and a role score from any public HTML page.
